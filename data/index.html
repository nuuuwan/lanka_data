Machine-readable source registry. This lists metadata endpoints, not datasets or observations. The build publishes only local configuration and instructions; it does not download metadata or data.

Retrieval procedure

  1. Identify the subject, year, place, geographic level and breakdown requested.
  2. Fetch the live metadata links above. Each index maps keys such as House/Time+District+CookingFuel/Count to relative data-file paths. Match the entity, set of dimension names and aggregate; order can vary. Do not assume separate dimensions can be combined into an unavailable cross-tabulation.
  3. For each relevant path, append it to that source's base URL with a slash and fetch the file. Verify year and region in the contents; filenames and metadata keys alone do not establish every available value.
  4. Read the nested JSON: entity → dimension:value → … → aggregate → typed value. For example, an integer count is encoded as Int:123. Select only the requested coordinates and preserve the metric's type and unit.
  5. State the observation year, geography and unit. Cite the exact upstream data file and the official source. Missing rows are not zero; do not add overlapping geographic levels, years, totals or duplicate observations.

Census attribution: Department of Census and Statistics of Sri Lanka. Election attribution: Elections Commission of Sri Lanka. The files are served through the intermediary repositories used by the app. The API guide explains how to select the appropriate citation.

GitHub Pages hosts the app and these instructions; it does not execute queries or publish raw query results. Use upstream files directly, the interactive JSON download, or the local query endpoint. If retrieval fails or the metadata does not provide the requested combination, explain the gap instead of inventing a result.
